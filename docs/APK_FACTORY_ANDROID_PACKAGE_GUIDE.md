# מדריך קבוע: קליטה, ניתוח ופירוק חבילות Android ב־APK Factory

מדריך זה הוא נקודת הכניסה הקבועה לכל עבודה עתידית עם APK, Split APK, APKM, XAPK ו־APKS.

## 1. בחירת מסלול

| מטרה | מסלול |
|---|---|
| בדיקת חבילה שהורדה מקישור | **Inspect Android APK Bundle from URL** |
| שחזור פרויקט שכבר נותח בריצה קודמת | **Rebuild and Sign Reverse-Engineered APK** עם `source_run_id` |
| בנייה מחדש מקישור ישיר, כשיש הרשאה מפורשת | **Rebuild and Sign Reverse-Engineered APK** עם `source_url` |
| בניית אפליקציה מהמקור שבמאגר | Workflow הבנייה הרגיל של אותו פרויקט |

## 2. הפעלת ניתוח מקישור (מומלץ לקליטה ראשונית)

1. פתח GitHub → Issues → Issue מספר 1 במאגר.
2. הוסף תגובה בפורמט הבא:

```text
/inspect-split-url HTTPS_DIRECT_DOWNLOAD_URL project-slug
```

3. מותר להשתמש בקישור HTTPS ישיר ל־APK, APKM, XAPK, APKS או ZIP.
4. ה־Workflow יוריד את החבילה ב־GitHub Actions, יחלץ אותה לתיקיית עבודה זמנית ויבדוק את רכיביה.
5. בסיום תופיע תגובה עם קישור לריצת Actions. בתוך הריצה נמצא Artifact בשם `apk-bundle-inspection-project-slug`.

אפשר גם להפעיל דרך Actions → **Inspect Android APK Bundle from URL** → Run workflow, ולהזין את הקישור בשדה `source_url`.

## 3. מה כולל דוח הניתוח

- בדיקת תקינות ארכיון וחילוץ בטוח.
- זיהוי APK בסיסי ורכיבי Split.
- מזהה חבילה לכל רכיב ואימות התאמה בין הרכיבים.
- גרסה, SDK, Activity להפעלה והרשאות שמופיעות ב־badging.
- אימות חתימה מקורית וטביעת SHA-256 לכל APK.
- SHA-256 של קובץ המקור ורשימת רכיבים וגדלים.
- שמירת manifest של XAPK, אם קיים, וקובצי OBB במרחב העבודה.

**מסלול הניתוח אינו מפענח קוד מקור, אינו משנה APK, אינו חותם מחדש ואינו מפרסם את קובצי ה־APK.** הוא מעלה Artifact טקסטואלי בלבד.

## 4. בנייה מחדש

לבנייה מחדש של אפליקציה שיש לך בעלות עליה או הרשאה מפורשת לשנות:

1. השתמש ב־**Rebuild and Sign Reverse-Engineered APK**.
2. בחר מקור אחד בלבד: `source_run_id` או `source_url`.
3. הגדר `project_slug` פשוט באנגלית.
4. אשר את ההרשאה ואת ההבנה שתוצרי Actions במאגר ציבורי עשויים להיות גלויים לציבור.
5. ודא שקיימים Secrets של מפתח החתימה הקבוע של APK Factory.
6. בדוק את תוצאת הבנייה, חתימת המקור וחתימת התוצר.

### תאימות לעדכון

- התקנה כעדכון דורשת אותו package ID, חתימה תואמת ו־versionCode מתאים.
- אי אפשר לשחזר מפתח חתימה פרטי מתוך APK.
- אם חתימת המקור אינה זהה למפתח APK Factory, התוצר לא יוכל להתקין כעדכון מעל המקור.
- יש להתקין את כל רכיבי ה־Split יחד; התקנת base בלבד אינה מספיקה לחבילה מפוצלת.
- קובצי OBB נלווים צריכים להישמר ולהיות מותקנים/ממוקמים לפי דרישות האפליקציה.
- אין לפרסם תוצר חלקי אם אחד מרכיבי ה־Split נכשל.

## 5. פורמטים ומגבלות קליטה

- נתמכים: APK, APKM, XAPK, APKS ו־ZIP שמכיל קובצי APK.
- קישור חייב להיות HTTPS ישיר להורדה, לא דף HTML של אתר.
- מגבלת ההורדה הנוכחית: 1 GiB.
- הארכיון נבדק נגד נתיבים מסוכנים, קבצים כפולים, APK מוצפן וחריגה ממספר/גודל רכיבים.
- קישור חתום זמני עשוי לפוג; במקרה של שגיאת 403/Expired יש להפיק קישור חדש.
- קישורים שמופיעים בתגובת Issue במאגר ציבורי גלויים למי שיכול לראות את המאגר. אין להדביק בהם סיסמאות או אסימונים לחשבונות אישיים. קישור הורדה זמני לקובץ ציבורי עשוי להיות בר־שימוש עד פקיעתו.

## 6. מבנה העבודה הקבוע

- קובצי המקור וכלי העזר נשמרים במאגר APK Factory.
- קובצי הורדה זמניים נשארים ב־runner ולא נכתבים ל־Git.
- דוחות ניתוח נשמרים כ־Actions Artifacts לתקופה מוגבלת.
- לפני שינוי Workflow: לקרוא את הקובץ הקיים ולשמור על מסלולי הבנייה שעובדים.
- לפני כל פרסום APK: לבדוק package ID, versionCode, חתימה, SHA-256 והצלחת build.
- לא לטעון שהתקנה או תאימות עדכון נבדקו בלי בדיקה אמיתית במכשיר.

## 7. פקודות שימוש מהירות

ניתוח חבילה מקישור:

```text
/inspect-split-url https://example.invalid/app.xapk app-inspection
```

בנייה מחדש מתוך ריצת reverse-engineering קודמת (רק בהרשאה):

```text
/rebuild-reconstructed-authorized RUN_ID project-slug ORIGINAL_CERT_SHA256
```

הערה: פקודת הבנייה הקיימת דורשת את אישורי ההרשאה שמוגדרים ב־Workflow. אין להשתמש בה ליצירת גרסה נגזרת של תוכנה קניינית ללא הרשאה.
