# מפרט קבוע — שש בקשות הממשק של אפליקציית משנת יוסף

מסמך זה נועד לשימוש חוזר בכל גרסה עתידית. יש לקרוא אותו לפני שינויי ממשק, לבדוק את הקוד העדכני ולהתאים את המימוש למבנה הקיים. אין להעתיק מספרי שורות או קטעי קוד ישנים באופן עיוור.

קובץ Java שבו בוצעו שינויים בעבר:
`apps/mishnat-yosef/app/src/main/java/org/mishnatyosef/mobile/MainActivity.java`

## 1. הודעת הסבר בכניסה למסך ההזמנה

**מטרה:** בכניסה למסך ההזמנה להציג חלון הסבר שמבהיר שלחיצה על פלוס או מינוס מעדכנת את הכמות ישירות מול השרת. בחלון תהיה תיבת סימון „אל תציג הודעה זו שוב”.

**מימוש:**
1. לזהות את נקודת הכניסה למסך ההזמנה, ולחבר אליה הצגת הודעה חד-פעמית לכל כניסה מתאימה — לא לכל רענון או טעינת מוצרים.
2. להציג את ההסבר באמצעות מנגנון Android מתאים, למשל `AlertDialog`, ובו תיבת הסימון.
3. לשמור את הבחירה באמצעות `SharedPreferences` במפתח ייעודי, למשל `skip_order_notice`.
4. לפני הצגת ההודעה לבדוק אם המשתמש ביקש שלא להציגה שוב. אם כן, להמשיך ישירות למסך.
5. ההודעה אינה אמורה לחסום או לשנות טעינת מוצרים, יצירת הזמנה או עדכון כמויות.

**בדיקות:** ההודעה מופיעה כשצריך; סימון „אל תציג שוב” נשמר גם לאחר סגירת האפליקציה; פלוס ומינוס ממשיכים לפעול כרגיל.

## 2. גוון כפתור המינוס

**מטרה:** לתת לכפתור המינוס רקע קרם-אפרסק בהיר ועדין, בלי לשנות את הפלוס, הצורה, המידות או פעולת הכפתור.

**הגוון העדכני המדויק:** `Color.rgb(255, 247, 239)`.

**מימוש:** לאתר את יצירת כפתור המינוס ולשנות רק את צבע הרקע שלו. בקוד הקודם נעשה שימוש בצורה דומה ל-`roundBtn("−", heightDp, Color.rgb(255, 247, 239), ORANGE_DARK)`. אם גרסה חדשה משתמשת ב-`Drawable` או ב-`ColorStateList`, להתאים את הצבע למנגנון הקיים. לבדוק שגם מצב הלחיצה אינו מחליף את הגוון באופן לא רצוי.

## 3. עדיפות מיון לקטגוריית „ביצים”

**מטרה:** לתת לקטגוריית „ביצים” מיקום מיוחד בסדר הקטגוריות, בלי לסנן או להסתיר מוצרים ובלי לשנות את כללי המיון האחרים.

במימוש הקודם הופיע כלל דומה ל:
`if (categoryName(p).contains("ביצים")) return 15;`

**מימוש:**
1. לאתר את פונקציית מיון הקטגוריות בגרסה העדכנית.
2. להבין את משמעות ערכי העדיפות ביחס לשאר הקטגוריות.
3. להוסיף או לשמר כלל שמזהה את קטגוריית הביצים ונותן לה את העדיפות המבוקשת.
4. לוודא שהכלל משפיע על הסדר בלבד, לא על הנתונים, המוצרים או פעולות ההזמנה.
5. אם ערך העדיפות השתנה במערכת המיון החדשה, להתאים אותו כך שהתוצאה בפועל תהיה המיקום הרצוי; לא להעתיק את המספר 15 בלי לבדוק.

**בדיקות:** קטגוריית הביצים נמצאת במקום הרצוי; שאר הקטגוריות ממשיכות להתמיין כרגיל; שום מוצר לא נעלם.

## 4. כפתורי קפיצה לתחילת רשימת המוצרים ולסופה

**מטרה:** להוסיף כפתור „למעלה” וכפתור „למטה” שמאפשרים לקפוץ לתחילת רשימת המוצרים ולסופה, בלי לשנות את מבנה המסך באופן שמפריע לחיפוש, לקטגוריות או לגלילה.

**מימוש מומלץ:**
1. לזהות את רכיב הגלילה האמיתי שבו מוצגים המוצרים.
2. להוסיף את הכפתורים מחוץ לתוכן המוצרים הגולל, במיקום נגיש שאינו מכסה מוצרים או בקרי כמויות.
3. לחבר את „למעלה” לתחילת אותו רכיב ואת „למטה” לסופו. עבור `ScrollView` להשתמש בפעולת הגלילה המתאימה; עבור `RecyclerView` לגלול לפריט הראשון או האחרון. אין ליצור רכיב גלילה שני.
4. להעדיף גלילה חלקה אם הרכיב הקיים תומך בכך.
5. לטפל ברשימה ריקה או בטעינה הדרגתית בלי קריסה ובלי לולאות גלילה.
6. לבחור מיקום שאינו מקטין משמעותית את שטח המוצרים ואינו מסתיר את החיפוש או את הקטגוריות.

**בדיקות:** שני הכפתורים מגיעים ליעד; גלילה ידנית ממשיכה לעבוד; הכפתורים לא מכסים מוצרים; הם פועלים גם כשהרשימה קצרה או נטענת.

## 5. שלושה מוצרים בכל שורה, עם כרטיסים קטנים יותר

**מטרה:** להציג שלושה מוצרים בכל שורה במקום שניים, ולהקטין את מידות רכיבי הכרטיס כדי להתאים לרוחב המצומצם.

**ערכי היעד:**
- מספר עמודות: **3**
- גודל תמונה: **100dp**
- גודל שם המוצר: **11sp**
- גובה בקרי הכמות: **32dp**

**מימוש:**
1. לזהות את רכיב הרשימה ואת אופן חלוקת המוצרים לשורות.
2. להגדיר שלוש עמודות במנגנון הפריסה הקיים. אם הקוד משתמש בלולאה שמחלקת מוצרים לשורות, להתאים את האינדקסים לשלושה פריטים בשורה; אם נעשה שימוש ב-`GridLayoutManager` או ברכיב דומה, לשנות את מספר העמודות שם.
3. להגדיר את התמונות ל-100dp, תוך שמירה על יחס התמונה ומנגנון הטעינה הקיים.
4. להגדיר את שם המוצר ל-11sp.
5. להגדיר את גובה בקרי הכמות ל-32dp.
6. לוודא שהמרווחים והרוחבים מאפשרים להציג את כל הרכיבים בלי חפיפה, ושהשורה האחרונה מוצגת גם כשמספר המוצרים אינו מתחלק בשלוש.

**כללים:** אין לשנות את סדר המוצרים, טעינת התמונות, יצירת ההזמנה או עדכון הכמויות כחלק משינוי הפריסה.

**בדיקות:** שלוש עמודות; תמונות 100dp; טקסט 11sp; בקרי כמות 32dp; אין חיתוך או חפיפה; השורה האחרונה תקינה.

## 6. להצמיד את החיפוש ואת שורת הקטגוריות לאזור עליון קבוע

**מטרה מדויקת:** גם שורת החיפוש וגם שורת הקטגוריות צריכות להיות חלק מאותו **אזור עליון קבוע**. שתיהן צריכות להישאר גלויות בזמן שגוללים ברשימת המוצרים. החיפוש אמור להצטרף לשורת הקטגוריות כחלק מאזור הכותרת הקבוע — אין להשאיר את החיפוש במקום נפרד שנעלם בגלילה. בהתאם למבנה העיצוב, החיפוש והקטגוריות יכולים להיות בשורות סמוכות בתוך אותו אזור קבוע; אין הכרח לדחוס אותם לאותה שורה אופקית אם הדבר יפגע בשימושיות.

**הבעיה בניסיון הקודם:** הועברו `toolbar` ו-`modeRow` אל `topHolder`, וסוג `topHolder` שונה מ-`FrameLayout` ל-`LinearLayout` אנכי. בעקבות זאת שורת החיפוש נעלמה. אין לחזור על ההעברה או על החלפת סוג המיכל באופן אוטומטי. יש לבדוק את היררכיית התצוגה בפועל ולמצוא את הסיבה המדויקת.

**מימוש מומלץ:**
1. למפות את רכיב החיפוש, שורת הקטגוריות, `toolbar`, `modeRow`, `topHolder` ורכיב הגלילה של המוצרים. לבדוק מי מכיל כל רכיב ומה גובהו ואופן הפריסה שלו.
2. לזהות אם החיפוש והקטגוריות נמצאים כרגע בתוך אותו אזור גולל עם המוצרים. אם כן, להוציא אותם מאזור הגלילה ולהציבם יחד באזור העליון הקבוע.
3. לשמר את רכיב החיפוש המקורי, את שדה הקלט, מאזיני החיפוש והסינון. אין למחוק אותו, ליצור כפילות שלו או להעביר את כל ה-`toolbar` בלי לבדוק אילו רכיבים נוספים הוא מכיל.
4. לשמור על סדר הגיוני באזור העליון: החיפוש והקטגוריות נשארים גלויים יחד, כשהקטגוריות נמצאות באזור שמעל רשימת המוצרים. אם העיצוב הקיים מציג חיפוש מעל הקטגוריות, יש לשמור על הסדר הזה.
5. להשאיר את רשימת המוצרים ברכיב גלילה נפרד מתחת לאזור העליון הקבוע. יש להקצות לה את יתרת גובה המסך באמצעות מנגנון הפריסה המתאים, ולא להסתמך על גובה קשיח שעלול לחתוך את התוכן.
6. לא לשנות את סוג `topHolder` רק כדי לנסות לפתור את הבעיה. `FrameLayout` ו-`LinearLayout` מתנהגים אחרת; לבחור את המיכל לפי מבנה המסך הנדרש. אם יש צורך במיכל נוסף, להוסיף אותו באופן ממוקד בלי לשבור את ההיררכיה הקיימת.
7. בעת בחירת קטגוריה, להמשיך לעדכן את רשימת המוצרים באמצעות הלוגיקה הקיימת.
8. לבדוק את המסך בגודל קטן, בזמן שהמקלדת פתוחה, לאחר החלפת קטגוריה ובזמן טעינת מוצרים. לוודא שכל המוצרים עדיין נגישים בגלילה.

**אסור:** להעלים את החיפוש; להציג חיפוש כפול; להשאיר את החיפוש מחוץ לאזור הקבוע; להחליף סוג מיכל בלי לבדוק את השפעתו; להכניס את המוצרים לאזור שאינו גולל; לשנות את לוגיקת החיפוש או ההזמנה.

**בדיקות קבלה:**
- החיפוש גלוי ומתפקד בכניסה למסך.
- החיפוש ושורת הקטגוריות נשארים יחד באזור העליון הקבוע בזמן גלילת המוצרים.
- שורת הקטגוריות נמצאת מעל רשימת המוצרים.
- בחירת קטגוריה ממשיכה לעבוד.
- המוצרים גוללים בנפרד ואפשר להגיע עד סוף הרשימה.
- אין חפיפה, שטח ריק חריג או חיתוך של התוכן.

## סדר ביצוע ובדיקות

1. לבדוק את הגרסה העדכנית ואת מבנה המסך.
2. לממש ולבדוק את שינוי 1.
3. לממש ולבדוק את צבע המינוס בשינוי 2.
4. לממש ולבדוק את עדיפות הביצים בשינוי 3.
5. לממש ולבדוק את שלוש העמודות ומידות הכרטיסים בשינוי 5.
6. לממש את שינוי 6 ולוודא שהחיפוש והקטגוריות קבועים יחד.
7. רק לאחר שמבנה הגלילה יציב, לממש את כפתורי הקפיצה של שינוי 4.
8. לבנות את ה-APK ולתקן שגיאות. אם אפשר, להתקין ולבדוק במכשיר.
9. לדווח בנפרד מה שונה, האם הבנייה הצליחה, והאם הממשק נבדק בפועל. אין לטעון שהאפליקציה עובדת בלי בדיקה מתאימה.

## הוראה להפעלה בשיחה עתידית

יישם את כל שש הבקשות במסמך זה על הגרסה העדכנית של משנת יוסף. התאם את המימוש למבנה הקוד הקיים, אל תעתיק שורות ישנות באופן עיוור ואל תשנה לוגיקה שאינה קשורה. חשוב במיוחד: שינוי 6 חייב להצמיד **גם את החיפוש וגם את שורת הקטגוריות** לאותו אזור עליון קבוע, כך ששניהם יישארו גלויים בזמן גלילת המוצרים. שינוי 4 צריך להשתמש ברכיב הגלילה הקיים. בנה ובדוק את האפליקציה ודווח בכנות על מה שהצליח בפועל.
